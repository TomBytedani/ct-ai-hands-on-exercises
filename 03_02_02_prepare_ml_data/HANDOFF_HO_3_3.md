# Maintainer handoff: HO-3.3.2 and HO-3.3.3

This document is the implementation contract for agents building the two
exercises that follow HO-3.2.2. It is not an answer key for the learner. Do not
add performance results to this file or expose the test set before the final
step of HO-3.3.3.

## Upstream objective and prediction boundary

HO-3.2.2 prepares UCI `bank-additional-full.csv` for a binary classification
task and trains one fixed baseline pipeline. The prediction is made
**immediately before a scheduled marketing call begins**. The positive class is
`subscribed=1`.

The prepared data deliberately excludes `duration`: UCI documents that it is
known only after the call and is therefore invalid for this prediction
boundary. Literal `unknown` values remain explicit categorical values.
`pdays=999` becomes missing `pdays` plus `previously_contacted=0`.

### `artifacts/split_assignments.csv`

Contains only `source_row_id` and `split`. The split values and fixed sizes are:

| Split | Rows | Permitted role |
| --- | ---: | --- |
| `train` | 24,712 | Fit preprocessing and model parameters |
| `validation` | 8,238 | Evaluate the baseline and compare development candidates |
| `test` | 8,238 | One final check of the selected HO-3.3.3 configuration |

Membership was created with two stratified `train_test_split` calls using seed

### `artifacts/baseline_model.joblib`

A fitted scikit-learn `Pipeline` with:

- numeric median imputation followed by `StandardScaler`;
- categorical constant-`unknown` imputation followed by
  `OneHotEncoder(handle_unknown="ignore")`;
- `LogisticRegression(solver="lbfgs", C=1.0, max_iter=2000,
  class_weight=None)`.

It was fitted using training rows only. It expects the 20 full feature columns
in the order recorded by the manifest. It does not accept `source_row_id` or
`subscribed` as inputs.

Only load this trusted repository-generated joblib file. Joblib/pickle formats
can execute code while loading and are not safe for untrusted files. Regenerate
the artifact when its recorded Python, pandas, joblib, or scikit-learn versions
do not match the active environment.

### `artifacts/manifest.json`

## HO-3.3.2 contract

The exercise objective is to evaluate the already-trained classification model
using accuracy, precision, recall, and F1-score.

The implementing agent shall:

1. Validate the manifest, file presence, schema, row membership, and dependency
   versions before loading the model.
2. Select **validation** rows only and keep test rows sealed.
3. Ask the learner to predict how class imbalance may affect accuracy before
   revealing model output.
4. Obtain validation predictions once from the unchanged baseline model.
5. Reconstruct TP, TN, FP, and FN with `subscribed=1` as positive.
6. Have the learner calculate all four formulas from the counts before using
   scikit-learn functions to verify them.
7. Explain why the metrics differ and which errors each metric exposes. Do not
   tune, refit, change the decision threshold, or select another model.
8. Persist no modified model and do not report any test metric.

Use `zero_division=0` for defensive metric calls, although the verified
baseline is expected to predict both classes. Do not copy validation results
into this handoff document or the HO-3.2.2 starter.

## HO-3.3.3 contract

The exercise objective is to observe the effects of model and dataset
combinations on training time and ML functional performance.

The reduced/core feature set is the full set minus the five economic-context
features:

```text
emp_var_rate
cons_price_idx
cons_conf_idx
euribor3m
nr_employed
```

Compare exactly these three candidates:

| Candidate | Model | Dataset combination |
| --- | --- | --- |
| A | Logistic regression with the upstream fixed settings | Core 15-feature set |
| B | Logistic regression with the upstream fixed settings | Full 20-feature set |
| C | `RandomForestClassifier(n_estimators=200, random_state=42, n_jobs=1, class_weight=None)` | Full 20-feature set |

For every candidate:

- construct a fresh preprocessing-and-model pipeline;
- for logistic regression, use the upstream numeric and categorical pipelines;
- for random forest, keep numeric median imputation and the upstream
  categorical pipeline but omit numerical scaling because it is not applicable
  to tree split ordering;
- fit training rows only;
- measure only the `.fit(...)` call with `time.perf_counter()`;
- calculate accuracy, precision, recall, and F1 on validation rows;
- use identical split membership and positive-class semantics.

Select the candidate with the highest validation F1. Break an exact F1 tie by
lower measured fit time. Lock the selection before touching test data. Refit a
fresh instance of the winning configuration on the combined training and
validation rows, then calculate the four metrics once on the untouched test
rows. Do not select a random seed, feature set, threshold, or model in response
to test performance.

Training-time results are environment-specific observations, not permanent
properties of the algorithms. Record CPU/runtime context and avoid claims based
on tiny timing differences.

## Shared guardrails

- Keep the historical Portuguese 2008–2010 context visible.
- Retaining age, job, marital status, education, and financial-status fields is
  an educational baseline choice, not an endorsement of real-world profiling.
- Do not expand these chapter 3 exercises into formal bias,
  representativeness, label-correctness, data-pipeline, drift, or production
  readiness testing; those belong to later syllabus objectives.
- Never restore `duration` to a leakage-safe feature set.
- Never fit imputers, encoders, scalers, or classifiers on validation/test rows
  before the explicitly specified final train-plus-validation refit.
- Do not treat the old benchmark as representative of contemporary customers
  or other countries, banks, products, or contact channels.

## Downstream acceptance checks

Before either later notebook runs, assert that:

- all four artifacts exist and the manifest schema is supported;
- the raw source hash matches the manifest;
- prepared row IDs are unique and exactly covered by split assignments;
- split sets are disjoint and have the fixed sizes above;

- the model pipeline reloads under the pinned trusted environment.

If a check fails on the normal learner path, stop with a remediation message
directing the learner to rerun and complete HO-3.2.2. If it fails while using
the maintainer override, report the invalid reference fixture instead. Do not
silently rebuild, resplit, fall back between locations, or substitute a
different model.
