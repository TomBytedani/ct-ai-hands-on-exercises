# Lab 3.3.3 — Compare models and dataset combinations

This guided lab addresses **HO-3.3.3 (H2)** from the CT-AI v2.0 syllabus:

> Use different ML models and dataset combinations to observe their effect on
> model training and final behavior. Observe training times and ML functional
> performance metrics.

The notebook compares exactly three predetermined candidates: logistic
regression with the 15-feature core dataset, logistic regression with all 20
features, and a 200-tree random forest with all 20 features. Every candidate is
a fresh preprocessing/model pipeline fitted on the same training membership and
evaluated on the same validation membership.

## Prerequisite and independence

Complete HO-3.2.2 through artifact creation first. HO-3.3.3 assumes the metric
concepts from HO-3.3.2, but it does not read or require any file generated by
that exercise.

Normal learner execution reads `../03_02_02_prepare_ml_data/artifacts`.
Maintainers may set `CTAI_HO_3_2_2_ARTIFACTS` to a trusted canonical fixture.
An invalid override fails clearly and never falls back. Because joblib loading
can execute code, never use an untrusted model artifact.

## Learning perimeter

The exercise:

- fits every development candidate on training rows only;
- measures only each `.fit(...)` call with `time.perf_counter()`;
- reports validation accuracy, precision, recall, F1, and measured fit time;
- selects by validation F1, using lower fit time only for an exact F1 tie;
- locks the winner before opening test rows;
- refits one fresh winning pipeline on train plus validation and evaluates it
  once on test.

It does not tune hyperparameters or thresholds, choose from test results, or
make claims about production readiness. Timing is an environment-specific
observation. The historical Portuguese 2008–2010 benchmark is retained for a
bounded educational comparison and does not endorse demographic or financial
profiling.

start without opening a browser automatically.

## How to work

1. Follow `guided_lab.ipynb` from top to bottom.
2. Answer every numbered prediction or interpretation prompt before continuing.
3. Use only the matching checkpoint in `learning_log.md` when directed.
4. Never open the test artifact manually; the notebook opens it after the
   validation winner is locked.
5. Stop after the single final test and do not revise the choice in response.
